# ربات الینالیزه 🤖💗

## 🆕 تغییرات نسخه جدید
1. **ارتقای اسپویلر**: اگر پیام هدف خودش ریپلای روی پیام دیگری بود، محتوای اسپویلرشده هم روی همون
   پیام ریپلای می‌شود (زنجیره مکالمه حفظ می‌شود). تمام محتوای پیام (رسانه + کپشن/متن) اسپویلر می‌شود.
   بعد از ارسال، یک گزارش شامل «صاحب پیام اصلی» و «درخواست‌دهنده» (هر دو لینک‌دار) روی خود پیام
   اسپویلرشده ریپلای می‌شود.
2. **رفع باگ سکوت «لیزه خسته‌ام»**: قبلاً وقتی `restrictChatMember` خطا می‌داد (مثلاً چون ربات
   دسترسی «محدود کردن اعضا» نداشت)، خطا بی‌صدا قورت داده می‌شد و پیام موفقیت به‌اشتباه فرستاده
   می‌شد. الان تمام فیلدهای دسترسی صریحاً غیرفعال می‌شوند و اگر واقعاً محدودیت اعمال نشود، پیام
   خطای واضح (به‌جای پیام موفقیت دروغین) فرستاده می‌شود. همین اصلاح روی دستور «لیزه سکوت» هم اعمال شد.
3. **دستور جدید «لیزه سگتم»**: لیزه به پیام ریپلای می‌زند «برام هاپ هاپ کن». اگر پیام *بعدی* همان
   کاربر در گروه «هاپ هاپ» یا «هاپ» باشد ۵٪ علاقه اضافه می‌شود، وگرنه ۱۰٪ علاقه کم می‌شود و لیزه
   به همان پیام بعدی ریپلای می‌زند. هر کاربر هر ۱ ساعت یک‌بار می‌تواند این چالش را شروع کند.
4. **تغییر نام مقام از پنل مدیریتی**: در جزئیات هر مقام داخل پنل («لیزه پنل») دکمه «✏️ تغییر نام
   مقام» اضافه شد. برای ادمین مادر و مقام‌دارانی که دسترسی جدید `renameRank` را دارند فعال است.
5. **دستور جدید «لیزه توهین»** (شوخی گروهی): با ریپلای روی پیام کسی، یک جمله شوخی/توهین‌آمیز
   تصادفی از لیست، در پاسخ به همان شخص فرستاده می‌شود. لیست پیش‌فرض در `messages.json`
   (`userCommands.insult.defaults`) است؛ ادمین مادر می‌تواند با `لیزه تنظیم توهین <متن>` مورد اضافه و
   با `لیزه حذف توهین <متن>` مورد حذف کند (موارد اضافه‌شده در دیتابیس ذخیره می‌شوند).
6. **ریپلای در صبح‌بخیر/شب‌بخیر**: دستورات «لیزه صبح بخیر» و «لیزه شب بخیر» حالا به پیام خود
   شخص ریپلای می‌زنند.

## 🆕🆕 قابلیت‌های نسخه بعدی

### ۱. کامنت‌گذاری هوش مصنوعی روی پست‌های کانال (پیش‌فرض خاموش)
کانالی که در `.env` مشخص می‌کنید (`CHANNEL_ID`) باید یک گروه بحث (discussion group) لینک‌شده
داشته باشد که همین ربات هم عضو/ادمین آن است. وقتی پستی در کانال منتشر می‌شود، تلگرام خودش
آن را به‌صورت خودکار در گروه بحث فوروارد می‌کند؛ ربات این فوروارد خودکار را تشخیص می‌دهد،
**۲ دقیقه** صبر می‌کند (قابل تغییر با `CHANNEL_COMMENTARY_DELAY_MS`)، بررسی می‌کند پست هنوز در
کانال هست یا حذف شده، و اگر بود، با استفاده از [OpenRouter](https://openrouter.ai) (طبق شخصیتی
که در `src/data/personality.json` تعریف کردید) یک کامنت کوتاه می‌سازد و روی همان پست در گروه
ریپلای می‌زند.

**راه‌اندازی:**
1. ربات را به کانال اضافه و **ادمین** کنید (حداقل با دسترسی ویرایش پیام‌ها).
2. کانال باید یک گروه بحث لینک‌شده داشته باشد و ربات باید عضو آن گروه هم باشد.
3. یک کلید رایگان از [openrouter.ai](https://openrouter.ai/keys) بگیرید.
4. در `.env`: `CHANNEL_COMMENTARY_ENABLED=true`، `CHANNEL_ID` (آیدی عددی کانال، با `-100` شروع
   می‌شود)، و `OPENROUTER_API_KEY` را پر کنید.
5. شخصیت الینالیزه را در `src/data/personality.json` (فیلد `systemPrompt`) هر طور دوست دارید
   ویرایش کنید - بدون نیاز به تغییر کد.

برای خاموش کردن این قابلیت، کافیست `CHANNEL_COMMENTARY_ENABLED=false` کنید (یا خالی بگذارید)،
دقیقاً طبق نیازمندی «قابلیت خاموش و روشن کردن در کدها».

> **نکته فنی:** چون Telegram Bot API متد مستقیمی برای «چک کردن وجود یک پیام» ندارد، بررسی
> «آیا پست هنوز در کانال هست» با یک ترفند بی‌ضرر انجام می‌شود: تلاش برای ویرایش دکمه‌های پست
> (با همون مقدار خالی قبلی). اگر پیام حذف شده باشد تلگرام خطای «message to edit not found»
> می‌دهد؛ اگر باشد ولی چیزی عوض نشده باشد خطای «message is not modified» می‌دهد که یعنی هنوز
> هست. هیچ تغییر محسوسی در پست ایجاد نمی‌شود.

### ۲. ارسال استیکر بعد از N پیام در گروه
بعد از هر `STICKER_BURST_THRESHOLD` پیام معمولی در گروه (پیش‌فرض ۴۰، قابل تغییر در `.env`)،
ربات یک «بسته استیکر» تصادفی از `src/data/stickers.json` می‌فرستد. هر بسته یا `type: "single"`
(یک استیکر) است یا `type: "sequence"` (چند استیکر پشت‌سرهم و به ترتیب - مثلاً یک کاراکتر که هر
تکه بدنش یک استیکر جداست). برای گرفتن `file_id` یک استیکر، آن را برای ربات‌هایی مثل
`@RawDataBot` فوروارد کنید و مقدار `file_id` را کپی کنید، سپس داخل `stickers.json` جایگزین
مقادیر `PUT_..._HERE` کنید. تا وقتی حداقل یک بسته واقعی تعریف نشده باشد، این قابلیت چیزی
نمی‌فرستد (خطا هم نمی‌دهد). با `STICKER_BURST_ENABLED=false` قابل خاموش کردن است.

### ۳. شوخی «پام پلیس»
بعد از هر `PAM_POLICE_THRESHOLD` پیام در گروه (پیش‌فرض ۶۰)، ربات به آخرین کسی که پیام فرستاده
ریپلای می‌زند: «{نام‌کاربری لینک‌دار}\nخط بعدی – پام پلیس.» به همراه یک عکس تصادفی از
`src/data/pamPolicePhotos.json` (اگر تعریف شده باشد) و یک دکمه شیشه‌ای «👅 لیس زدن» که **فقط**
همان شخص هدف می‌تواند بزند. با زدن دکمه، یک پیام گزارش در گروه فرستاده می‌شود که آن شخص «پای
الینالیزه لیس زده» و ۵٪ به علاقه‌ی الینالیزه نسبت به او اضافه می‌شود؛ بعد از یک‌بار استفاده،
دکمه از پیام حذف می‌شود. با `PAM_POLICE_ENABLED=false` قابل خاموش کردن است.

> شمارنده‌های هر دو قابلیت سرگرمی فوق در حافظه (RAM) نگهداری می‌شوند، نه دیتابیس؛ چون این‌ها
> فقط برای یک بازی/شوخی زودگذرند و از دست رفتنشان با ری‌استارت ربات مشکلی ایجاد نمی‌کند.



ربات دستیار مدیریت گروه‌های تلگرامی، سرگرمی و ثبت داده - نوشته‌شده با Node.js + Telegraf + MySQL.

## نصب و راه‌اندازی

### ۱. پیش‌نیازها
- Node.js نسخه ۱۸ به بالا
- دسترسی به همان دیتابیس MySQL که ربات دیگرتان استفاده می‌کند (یا هر دیتابیس MySQL دیگری)
- یک توکن ربات از [@BotFather](https://t.me/BotFather)

### ۲. نصب پکیج‌ها
```bash
npm install
```

### ۳. تنظیم فایل env.
فایل `.env.example` را کپی کرده و به `.env.` تغییر نام دهید، سپس مقادیر را پر کنید:
```bash
cp .env.example .env
```
- `BOT_TOKEN`: توکن ربات از BotFather
- `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME`: اطلاعات همان دیتابیس مشترک شما
- `MOTHER_ADMIN_IDS`: آیدی عددی تلگرام ادمین‌های مادر، با کاما جدا شده (مثال: `111,222`)

> **نکته مهم:** جداول این ربات همگی با پیشوند `elinalize_` ساخته می‌شوند تا با جداول ربات دیگرتان که روی همین دیتابیس است تداخلی نداشته باشد. در اولین اجرا، اگر جداول وجود نداشته باشند، خودکار ساخته می‌شوند.

### ۴. اجرا
```bash
npm start
```
یا برای توسعه با ری‌استارت خودکار:
```bash
npm run dev
```

### ۵. اضافه کردن به گروه
ربات را به گروه اضافه کرده و **ادمین کامل** کنید (حداقل دسترسی‌های: حذف پیام، اخراج کاربر، بن کردن، محدود کردن کاربر).

## ساختار پروژه
```
src/
  index.js                 # نقطه ورود اصلی و دیسپچر
  config.js                 # تنظیمات مرکزی (از .env خوانده می‌شود)
  database/
    db.js                    # اتصال pool به MySQL
    init.js                  # ساخت خودکار جداول
  services/                 # منطق دسترسی به داده (مقام‌ها، اخطار، بن، علاقه/عصبانیت، ...)
  handlers/                 # پردازش دستورات و دکمه‌های شیشه‌ای
  middlewares/              # میان‌افزارهای Telegraf (اجرای بن، ثبت گروه)
  data/
    messages.json            # تمام متن‌ها و دیالوگ‌های فارسی ربات - آزادانه قابل ویرایش
  utils/                     # ابزارهای کمکی
```

## ویرایش پیام‌های ربات
تمام جمله‌هایی که ربات می‌گوید (پیام صبح‌بخیر، پاسخ ابراز علاقه، پیام‌های خطا و ...) داخل
`src/data/messages.json` هستند. کافیست این فایل را ویرایش کنید و ربات را ری‌استارت کنید؛
نیازی به تغییر کد نیست. برای فیلدهایی مثل `{name}` یا `{target}` در پیام‌ها، مقدار به‌صورت خودکار
جایگزین می‌شود.

## کلمات صدا زدن
پیش‌فرض: `الینالیزه` و `لیزه` (در `src/config.js` → `defaultWakeWords`).
هر ادمین مادر می‌تواند مستقیماً از داخل گروه کلمه جدید اضافه/حذف کند:
```
لیزه افزودن صدا زدن نازی
لیزه حذف صدا زدن نازی
```

## دستورات مقام‌دارها (نیاز به ریپلای روی پیام کاربر هدف)
| دستور | کار |
|---|---|
| `لیزه اخراج` | اخراج + مسدود کردن دائم (در صورت بازگشت، پیام‌هایش حذف می‌شود) |
| `لیزه حذف اخراج` | خارج کردن از لیست مسدودی‌ها |
| `الینالیزه قوانین` | ارسال قوانین گروه |
| `لیزه اسپویلر` | اسپویلر کردن پیام/رسانه ریپلای‌شده |
| `لیزه اخطار` | افزودن اخطار (با رسیدن به سقف، اخراج خودکار) |
| `الینالیزه حذف اخطار` | حذف یک اخطار |
| `لیزه حذف پیام` | حذف پیام ریپلای‌شده |
| `لیزه گزارش فعالیت` | فعالیت اخیر کاربر هدف |
| `لیزه نمایش مقام` | نمایش مقام کاربر هدف |
| `لیزه سکوت <عدد>` | سکوت به مدت N دقیقه، مثال: `لیزه سکوت 10` |
| `الینالیزه لیست زندانی` | لیست اخراج‌شده‌ها (صفحه‌بندی‌شده) |
| `لیزه لیست مجرمین` | لیست گزارش‌شده‌های تاییدشده (صفحه‌بندی‌شده) |
| `لیزه چه خبر` | گزارش فعالیت مقام‌ها در ۲۴ ساعت اخیر |

## دستورات کاربران عادی
| دستور | کار |
|---|---|
| `لیزه اخطار` (ریپلای) | ارسال درخواست گزارش برای تایید مقام‌دارها |
| `لیزه نمایش مقام` (ریپلای) | نمایش مقام شخص هدف |
| `لیزه صبح بخیر` / `لیزه شب بخیر` | پیام تصادفی صبح/شب بخیر |
| `لیزه دوست دارم` / `لیزه عاشقتم` | افزایش ۵٪ علاقه‌مندی الینالیزه (هر ۱ ساعت یک‌بار) |
| `لیزه پروفایل` | نمایش درصد علاقه/عصبانیت و تعداد اخطار |
| `لیزه خسته‌ام` | سکوت تصادفی بین ۲۰ دقیقه تا ۵ ساعت برای خودش |
| `لیزه سگتم` | چالش «هاپ هاپ» - پاسخ درست تا پیام بعدی: ۵٪+ علاقه، پاسخ غلط: ۱۰٪- علاقه (هر ۱ ساعت یک‌بار) |
| `لیزه توهین` (ریپلای) | ارسال یک شوخی/توهین تصادفی به شخص ریپلای‌شده |

## دستورات ادمین مادر
| دستور | کار |
|---|---|
| `لیزه ساخت مقام <نام> <سطح>` | ساخت مقام جدید، مثال: `لیزه ساخت مقام پلیس شب 5` |
| `لیزه تنظیم مقام <نام مقام>` (ریپلای) | اختصاص مقام به کاربر هدف |
| `لیزه حذف مقام` (ریپلای) | حذف مقام از کاربر هدف |
| `لیزه تنظیم سقف اخطار <عدد>` | تغییر سقف اخطار قبل از اخراج خودکار |
| `لیزه تنظیم قوانین <متن>` | تنظیم متن قوانین گروه |
| `لیزه تنظیم توهین <متن>` | افزودن یک شوخی/توهین جدید به لیست دستور «لیزه توهین» |
| `لیزه حذف توهین <متن>` | حذف یک شوخی/توهین سفارشی از لیست |
| `لیزه پنل` | باز کردن پنل مدیریت مقام‌ها (دکمه‌ای) - هم در گروه هم در پیوی ربات |

در پنل می‌توانید برای هر مقام، تک‌تک دسترسی‌ها (اخراج، اخطار، سکوت، تغییر نام مقام‌ها و ...) را
روشن/خاموش کنید، سطح (priority) مقام را برای سلسله‌مراتب بالا/پایین ببرید، و با دکمه «✏️ تغییر
نام مقام» اسم مقام را عوض کنید (کافیست روی پیامی که ربات می‌فرستد نام جدید را ریپلای کنید).
مقام با سطح بالاتر نمی‌تواند توسط مقام پایین‌تر اخراج/حذف/تنظیم شود.

## سیستم علاقه‌مندی و عصبانیت
- هر ابراز محبت (`لیزه دوست دارم`) حداکثر هر ۱ ساعت یک‌بار، ۵٪ علاقه اضافه می‌کند.
- عصبانیت فقط با گذشت زمان کم می‌شود (۵٪ در روز، خودکار هر نیمه‌شب).
- تایید گزارش یک کاربر توسط مقام‌دار، ۱۰٪ عصبانیت اضافه می‌کند.
- اخراج کاربر توسط مقام‌ها: ۲۰٪ کاهش علاقه و ۴۰٪ افزایش عصبانیت.
- وقتی علاقه ۱۰۰٪ و عصبانیت ۰٪ شود: مقام موقت ۲۴ ساعته «عزیز الینالیزه» اعطا و در گروه تبریک
  گفته می‌شود، سپس ۵۰٪ از علاقه کم می‌شود.

## نکات فنی
- دیتابیس مشترک: تمام جداول با پیشوند `elinalize_` ساخته می‌شوند و در صورت نبودن، خودکار
  ساخته می‌شوند (`CREATE TABLE IF NOT EXISTS`) — هیچ تداخلی با جداول ربات دیگرتان ندارد.
- ادمین‌های مادر فقط از `.env` خوانده می‌شوند و در دیتابیس ذخیره نمی‌شوند.
- برای mute/سکوت از قابلیت بومی تلگرام (`restrictChatMember` با `until_date`) استفاده شده،
  پس نیازی به کرون‌جاب جداگانه برای پایان سکوت نیست.
- برای اسپویلر کردن رسانه، چون ربات‌ها نمی‌توانند فلگ اسپویلر پیام‌های دیگران را ویرایش کنند،
  پیام اصلی حذف و با `has_spoiler: true` دوباره توسط ربات ارسال می‌شود.

## توسعه بعدی پیشنهادی

- افزودن تست‌های خودکار (unit test) برای سرویس‌ها
